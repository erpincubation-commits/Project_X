Shared interaction patterns

PatternProposed behaviour
Navigation and accessPersistent, permission-scoped workspace navigation; section shortcuts show only actions the server permits. Preserve the current single-role and independent-approval rules.
Registers and detailShow filters, result count, stable pagination and a clear empty state. Open a record for status, owner, lines, next actions and history; do not imply that a list is a live notification.
Forms and draftsGroup fields by purpose; explain required fields and units. Keep draft data when validation fails. Warn before discarding edits or switching away; do not imply autosave.
Errors and retriesPlace field errors beside their inputs; show a plain-language outcome and reference for server failures. For an uncertain save, refresh or retry unchanged while the workspace remains open.
AccessibilityKeyboard access, visible focus, labelled controls, text as well as colour for status, accessible tables and meaningful headings. Test at 100–200% scale and with a screen reader.
Security and privacyNever display secrets in activity, logs or screenshots. Limit personal data, require independent approvals where implemented, and review exports before sharing.

End-to-end purchase flow

Request → independent decision → order → accepted receipt → three-way matched invoice → two independent payment approvals → record a transfer completed outside the ERP. Request, order and quotation views must not imply that they post a journal or send money.

Supplier returns, credit notes, quote award, RFQs, configurable budgets and automatic banking are future scope. Their UI is not represented as working actions.

Design and delivery handoff

Visual system: neutral work surface, restrained blue action colour, consistent 4/8/16/24 px spacing, clear typography, tabular numbers and compact tables. Status must remain readable without colour.

Evidence required: validate each screen against server permissions and real labels; run keyboard, screen-reader, scale, cross-role and failure-path reviews; reconcile financial scenarios; test backup, restore and signed deployment separately.

Reference: ERPNext's repository and procurement cycle informed the workspace grouping and linked flow. This proposal does not import ERPNext code or imply feature parity.
